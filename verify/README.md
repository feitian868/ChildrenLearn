# verify/ —— 题库回归测试

四个脚本都用 **Node 原生 ESM** 跑，不依赖任何 npm 包。它们注入可控的 `Date` 和 `localStorage`，**直接调用项目真实的 `tasks.js` / `store.js`**，从 2026-01-05（周一）连续模拟 365 天、三年级的抽题过程。

## 放置位置

脚本里的 import 写的是 `../assets/js/...`，所以 `verify/` 必须放在**项目根目录下**（与 `assets/` 同级）：

```
primary-quest/
├── assets/
├── index.html
└── verify/          ← 放在这里
    ├── sim_repeat.mjs
    ├── sim_depth.mjs
    ├── sim_static.mjs
    └── sim_logic.mjs
```

## 运行

```bash
cd verify
node sim_repeat.mjs
node sim_depth.mjs
node sim_static.mjs
node sim_logic.mjs
```

约几秒到几十秒（后期数据量大，属正常）。

## 各脚本看什么

| 脚本 | 输出重点 |
|---|---|
| `sim_repeat.mjs` | 全年题量、**题面级重复率**、分阶段/分科目重复率、高频模板、四科生成器跨 365 天的唯一签名数 |
| `sim_depth.mjs` | **认知重复**（Top N 问法覆盖率、单日同款峰值）、知识点 key 覆盖、`topic` 数、**localStorage 体积增长曲线** |
| `sim_static.mjs` | 静态题 vs 生成题占比；第 201 天清空 `recentQuestions` 模拟「换设备/清缓存」后的重复率 |
| `sim_logic.mjs` | 逻辑/场景题**占比与是否随时间枯竭**、按科目/知识点分布、逻辑池跨 365 天唯一供给、答案一致性抽查 |

## 注意

- 脚本**只读项目代码、不写项目文件**，`localStorage` 是内存 Map，跑完即消失，不会污染真实数据。
- 模拟的是理想路径（连续 365 天打开、不切年级、不导入备份）。真实使用中清缓存 / 换设备会让去重记录归零，`sim_static.mjs` 专门量化这个场景。
- `sim_repeat.mjs` 末尾那句「容量缺口 54 倍」是拿「单日候选池」比「全年需求」的固定池视角，因为生成题每天重建，它**不是真实容量约束**，别拿它当扩容依据。真实约束是「问法模板数」，看 `sim_depth.mjs`。
- 逻辑题的 `source` 统一标为「情境题 · xxx」，**不冒充教材原题**。新增内容由生成器产出，答案与科学性请家长抽检，别只扩数量不扩质量。
