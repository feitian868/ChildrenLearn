# verify/ —— 题库回归测试

四个脚本都用 **Node 原生 ESM** 跑，不依赖任何 npm 包。它们注入可控的 `Date` 和 `localStorage`，**直接调用项目真实的 `tasks.js` / `store.js`**，从 2026-01-05（周一）连续模拟 365 天、三年级的抽题过程。

## 放置位置

脚本里的 import 写的是 `../assets/js/...`，所以 `verify/` 必须放在**项目根目录下**（与 `assets/` 同级）：

```
primary-quest/
├── assets/
├── index.html
└── verify/          ← 放在这里
    ├── sim_repeat.mjs
    ├── sim_depth.mjs
    ├── sim_static.mjs
    ├── sim_logic.mjs
    ├── sim_course.mjs
    ├── sim_mastery.mjs
    └── sim_storage.mjs
```

## 运行

```bash
cd verify
node sim_repeat.mjs
node sim_depth.mjs
node sim_static.mjs
node sim_logic.mjs
node sim_course.mjs
node sim_mastery.mjs
node sim_storage.mjs
```

约几秒到几十秒（后期数据量大，属正常）。

## 各脚本看什么

| 脚本 | 输出重点 |
|---|---|
| `sim_repeat.mjs` | 全年题量、**题面级重复率**、分阶段/分科目重复率、高频模板、四科生成器跨 365 天的唯一签名数 |
| `sim_depth.mjs` | **认知重复**（Top N 问法覆盖率、单日同款峰值）、知识点 key 覆盖、`topic` 数、**localStorage 体积增长曲线** |
| `sim_static.mjs` | 静态题 vs 生成题占比；第 201 天清空 `recentByDay/recentKeys` 模拟「换设备/清缓存」后的重复率 |
| `sim_logic.mjs` | 逻辑/场景题**占比与是否随时间枯竭**、按科目/知识点分布、逻辑池跨 365 天唯一供给、答案一致性抽查 |
| `sim_course.mjs` | 阶段 A：教材题是否只来自「当前单元 + 已学单元」、允许集合 vs 全池、题量不足时的表现 |
| `sim_mastery.mjs` | 阶段 B：跨 100 天掌握度累积、错题 30 天内至少一次变式重现、weakKeys 对照实验、周报、每周 10 题小测、成长页曲线数据 |
| `sim_storage.mjs` | B′ 终检：**每天完整答题**（走 `applyTaskOutcome`）的 365 天真实存储曲线（门槛 3.6 MB），以及 ma-u01 收敛场景的内容缺口 |

## 阶段 A：课程结构收敛（`sim_course.mjs`）

```bash
node sim_course.mjs
```

看四个场景：未配置 / 学期中段（当前单元 5）/ 学期末退化（当前单元 14）/ 题量不足（当前单元 1）。

**「100% 来自当前/已学单元」的成立条件（别笼统写「验收通过」）：**

1. 分子分母**只算教材题**；`lg-*` 逻辑/情境题作为拓展题单列，不计入比例。
2. 允许集合 = 单元 `order ≤ 当前单元 order`（当前单元 + 已学单元）。
3. 教材题只能从允许集合抽，且抽到的每道教材题都必须落在允许集合内。
4. 学期末（当前单元 = 最后一个单元）允许集合≈全册，这里的 100% 是**退化场景**，不能单独拿来报达标；要看学期中段（当前单元 5）是否也 100%。
5. 教材题不足时**不向后扩围**（不提前学未学单元），当天题量可少于配额，`day.courseScope.math.shortage = true`。
6. 收缩项数而不是补足 3 项：每项 3~4 道、拓展 ≤2、拓展占比 ≤50%。固定种子已覆盖两种形态：「2 项 · 4 教材 + 4 拓展 = 50%」与「1 项 · 4 教材 + 0 拓展 = 0%」。

**阶段 B 前置边界（重要）：**

- `knowledge.prerequisites` 目前**只记录、不参与任何计算**；单元顺序 / 课名 / 先修关系尚未拿课本封面核对。
- 掌握度只能先挂 `knowledge.id`，先修链等课本核对通过后再启用。
- `version / grade / term` 继续保持留空，不按 `knowledge-*.js` 的 `source` 标签推断。


## 阶段 B：诊断闭环（`sim_mastery.mjs`）

```bash
node sim_mastery.mjs
```

覆盖 100 天（当前单元 = 5，含 5 个知识点）：

- **掌握度是累积对象**：`data.mastery.keys[knowledgeId] = {status,seen,correct,lastSeen,streak}`，只在任务完成时累加，**不从 `dailyHistory` 重算**（后者只留 90 天）。
- **键稳定 / 可迁移**：数学挂 `course-map` 的 `knowledge.id`，其他科目挂 `科目:topic`；`mastery.aliases` + 工作台「迁移 id」支持课本核对后整体改名。
- **间隔复习**：`data.reviewQueue` 是按日期分组的字符串数组（`kid~stage~origSig~lastSig~reason~level`），不每题一个对象；错题第 1 天回来，仍答错才推进 3/7/15/30 天。B′ 起签名为 24 位 Base36（5 字符），首次出错日期单独存 `data.reviewOrig[sig]`（按签名只存一份，不随队列重复）；读队列时兼容旧 32 位十进制签名（截断转换，与 `sig24` 同输入串逐位一致）。
- **变式口径**：只从现有题池里选「同 knowledge.id、题面与原题/上一次都不同」的题；没有变式就写进 `data.contentGaps` 交阶段 C，**不生成新题、不拿原题顶替**。
- **weakKeys**：`tasks.js` 的 `rankWeak()`（`getPool` 返回前排序）+ `pickQuestions()` 的 `weakShuffle()`；只改排序，不改题量/达标线。固定种子 20 次对照均值：带 weak 0.70/9.20（7.6%）vs 清空 0.05/9.20（0.5%）。效果受两条既有规则限制：同档内逻辑/拓展题先占位（`logicFirst`），且同一天同一科目同一知识点最多 1 题。
- **每周小测**：`math.html?quiz=1`，10 题、不提示、不重做、新旧知识点混合，结果单独存 `data.quizzes[weekKey]`，不加积分。「新」= **未达到 mastered 的知识点**（不是「新题面」），且只从当前 + 已学单元里选（实测 0 道越界）。headless 实测：第 1 题故意答错后 220ms 提示仍 `hidden`、无错因弹窗，900ms 自动进入第 2 题；结算页无「再练一次」，积分不变。
- **成长页**：`masteryTrend` 记录每日知识点掌握度，曲线 +「本周新掌握 N / 待复习 M」+ 家长一句结论。

当前实测（2026-11-06 起 100 天，当前单元 5，B′ 签名格式下复测）：
- 原始错题（非复习题）78 道，30 天内至少一次以变式重现 **78/78 = 100%**（验收口径：≥90%）；
- 五档命中（**观察指标、不作门槛**）：S1=78 / S2=59 / S3=55 / S4=53 / S5=33；完整走完 1→3→7→15→30 的错题 **33 道**；
- 每周小测：10 题（旧知识点 3 / 新知识点 7），结果单独存，不加积分、不重做；
- `dailyHistory` 裁掉第 1 天后掌握度 `seen 2 → 69` 仍连续；
- 曲线 5 条（近 30 天有记录的知识点，默认上限 6；课程表共 18 个知识点）。

**①「100%」的成立条件（不是无条件的）：**
1. 只统计**非复习题**首次答错，且原题日期 +30 天 ≤ 模拟末日；验收口径为「30 天内**至少一次**变式重现 ≥90%」；
2. 「同 origSig」= 变式来自同一条错题的队列条目（B′ 起 `origSig = sig24(type|prompt|answer)`，24 位 Base36）；
3. 「不同题面」= 变式 `promptSig` ≠ 原题，且 ≠ 上一次变式的 `lastSig`；
4. 变式只能来自**当天现有题池**，找不到就记 `contentGaps`，不算命中、也不拿原题顶替；
5. 该比例在**未收敛的全年级池**下成立；`currentUnitId=ma-u01` 收敛且全错时，40 天会记录 `表内乘法×373` 次内容缺口，不能拿 100% 掩盖供给不足。

**间隔点的口径：** 1/3/7/15/30 是「相对上一次复习」的间隔，不是相对原题的绝对天数；因此相对原题的累计天数为 +1/+4/+11/+26/+56，**S5 落在第 56 天**。某一档答对即终止后续间隔。五档完成率只作观察指标、不作门槛，不为凑数字压缩间隔。

**状态迁移公式（`seen` 只是次数，不等于掌握）：**
- 答对：`mastered` 当且仅当「已 mastered 且累积正确率 ≥75%」或「seen ≥3 且正确率 ≥80%」或「连续答对 streak ≥3 且正确率 ≥75%」；否则 `learning`。
- 答错：`review`（进入/推进间隔队列）。

## 内容缺口台账（阶段 C 按题型规格书补，B 不补内容）

1. **`ma-u01`（表内乘法）教材题供给不足** → **已产出 8 道 `pending-review` 题，家长 approved 后解决**。`ma-u01-c3-01`~`08` 问法互不相同，默认不进抽题池；**真人还没点过「通过」，孩子端仍是原来的 4 道 / 1 种问法**。approved 后可抽 **12 道题 / 9 种问法**（口径写死）。验收脚本 `sim_content.mjs` 只验证链路，不等于已放行。
2. **20 个知识点「≥4 题只有 1 种问法」**（`sim_content.mjs` 断言 ④，只报告不修）：`ma-u01-k1`、`ma-u03-k1`、`ma-u12-k1`、`ma-u13-k1`、science 配对类（18~84 道）等，完整清单见脚本输出。**后续内容轮按优先级补问法**；本阶段不生成新题。
   附注：`annotateQuestion` 会把「人教版数学2年级上册 · 表内乘法」出处标签挂进三年级上册单元；课程表骨架仍需按孩子课本封面核对（不修，避免用骨架推掌握度）。
3. **收敛到小单元后教材题供给枯竭**（C 收尾 P0-1b 实测，内容缺口，不算回归失败）：`currentUnitId=ma-u01` + 8 道全 approved、365 天完整答题，教材题平均 **4.58 道/天**（最少 4、最多 7，教材 ≥8 的天数 **0/365**）；**从第 5 天（2026-11-10）开始出现「拿旧题兜底」**，当天 2 道，365 天累计 1,629 道（占出题量 12.2%）。原因：ma-u01 内可新生成的教材题约 4 道/天，8 道手写题在 365 天不重题约束下 1~2 天用完；纯前端不允许一年内重题，只能兜底。**补内容优先**（下一内容轮按本台账第 2 条补问法），不靠放宽 365 天去重。
   同步实测（`sim_approved.mjs`）：收敛模式 365 天完整答题存储 **3.041MB** ≤3.6MB，`data.days=90`，项数最少 2、最多 3（不再收缩到 1）。
   **「12 道可抽 ≠ 每天 12 道」的约束链**（E 轮疑点④澄清，常数一个未动）：
   ① 模板上限 `MAX_TEMPLATE_PER_DAY=2`（tasks.js:54）——ma-u01 教材题中同 templateKey 的多道不能同一天全出；
   ② 每项配额：每天数学 2~3 项 × `QUESTIONS_PER_TASK=4`，其中 `MAX_REVIEW_PER_TASK=2` 要先给到期的错题变式占位，教材题只占余下位置；
   ③ 同知识点冷却 `COOLDOWN_DAYS=10`（tasks.js:52 定义、133-139 行让位逻辑）——ma-u01 只有 4 个知识点，轮过一遍后 10 天内互相让位，只能转向拓展或旧题；
   ④ `AVOID_DAYS=365`（tasks.js:51）——题面一年不重复，静态池逐日单调枯竭。
   ⇒ 四条叠加后教材实测供给 4~7 道/天；这是内容缺口，不是调度 bug；E 轮未为做漂亮而改任一 `MAX_*`。
4. weakKeys 对照实测 7.6% vs 0.5%（20 次均值 0.70 vs 0.05 道），效果被 `MAX_LOGIC_PER_TASK` 与「同科同知识点每天 1 题」两条既有规则压制；**保留现状**，收敛模式改为教材优先（C 收尾 ④），阶段 C 补题后重测再评估。
5. **「复习变式复用旧题面 0.36%」是统计口径，不是原题顶替**（E 轮疑点②澄清）：`findVariant`（mastery.js `findVariant`）硬约束 `promptSig ≠ origSig 且 ≠ lastSig`——原题与上一次变式双重排除；找不到变式只记 `contentGaps` 并丢弃该条目，绝不拿原题凑数。0.36% 的真实含义：被挑中的变式题面**此前曾作为普通题出现过**（题池在 365 天窗口内轮转），其签名命中 `recentByDay` 统计。E2 实测：14 天变式 53 道、原题签名复用 **0 道**（`sim_e2e.mjs` 环4 逐道断言）。
   **家长视角的口径说明（收尾3，不改代码/不改统计/不重算指标）**：家长在周报视野里仍会看到「0.36% 重复」这个非零数字——它不是「原题又出了一遍」，而是「变式题面此前作为普通题出现过」的统计命中；`findVariant` 已用 `promptSig ≠ origSig` **且** `≠ lastSig` 双重排除原题与上次变式。更干净的做法是把复习变式从重复统计里剔除，让家长看到 0.00%，但那要改统计实现，E 明文禁止，故本轮只做口径说明，指标值维持实测原样。
6. **检查器已知盲区：解析「写中间量 + 提到正确答案数值 + 结论指向错误数值」抓不到**（E 轮疑点⑤实证）：`checkExplainConsistent` 见解析含正确答案原文/数值即判「分步讲解」跳过（question-check.js `checkExplainConsistent` 第 170-172 行）。刁钻反例（答案 52；解析 `5 × 12 = 60，60 - 8 = 48，所以还剩 48 支（正确答案应为 52）`）如期漏报，已固化进 `sim_content.mjs` P1 自测第 4 道（`expectMiss`，如实记录、不计失败）。**「误报 0」不等于检查器可靠**；此盲区留待规则升级（例如「最后一个算式必须与答案一致」需先解决凑十/分步讲解的 41 道误报问题，见 C 轮迭代史）。

## 阶段 B′：存储紧凑化（已实施并验收）

四脚本只调 `ensureToday()`，测的是「生成任务但不答题」的空壳路径，因此 B 新增的 5 个字段全是空的。`sim_storage.mjs` 每天走真实链路（`ensureToday` → 逐项 `completeTask` → 每周 `saveQuizResult`），四科全做。B′ 后实测：

| 节点 | localStorage 字符 | UTF-16 | 掌握度知识点 | 复习条目 | 小测 | contentGaps | data.days |
|---|---|---|---|---|---|---|---|
| 30 天 | 475,775 | 0.907 MB | 107 | 35 | 4 周 | 8 | 30 |
| 90 天 | 1,375,170 | 2.623 MB | 122 | 64 | 12 周 | 20 | 90 |
| 180 天 | 1,423,374 | 2.715 MB | 136 | 133 | 12 周 | 31 | 90 |
| 365 天 | 1,517,527 | **2.894 MB** | 139 | 260 | 12 周 | 40 | 90 |

**结论：365 天 2.894 MB ≤ 3.6 MB 门槛，B′ 验收通过，可以进入阶段 C。**

体积构成（365 天）：`days` 1,233,613 字符（90 天封顶）+ `recentByDay` 111,636 + `recentKeys` 57,936 + `reviewOrig` 25,495 + `dailyHistory` 31,085；B 侧字段 `mastery` 16,913 + `reviewQueue` 13,081 + `trend` 20,242（45 天）+ `quizzes` 3,003 + `gaps` 4,019。

B′ 三条改动（一起做完，目标 ≤3.6 MB 并留余量）：
1. `recentQuestions`「每题 3 条 KV」→ `recentByDay`「按日期分组的签名数组」：当天同签名只存一次，体积约为原来 1/5（883,873 → 111,636 字符）；读时兼容旧格式（`migrateRecent`：`k:` → `recentKeys`、`s:<32位十进制>` 截断为 24 位 Base36 进 `recentByDay`、纯 id 条目丢弃——同内容必同签名，语义等价），写时只写新格式；
2. 队列与回避签名统一 24 位 Base36（`rng.sig24`）：碰撞只会「多回避/多排队」，不会「误重复/丢复习」；
3. `masteryTrend` 只保留 45 天（成长页仍画 30 天曲线）；**只裁 trend，`mastery.keys` / `reviewQueue` / `quizzes` 一律不裁**——它们是「跨 100 天不失忆」的载体（`mastery.js` / `store.js` 头部注释写死）。

不削减 `DAYS_KEEP`（「90 天历史」的产品承诺不变），不裁掌握度累积对象。

## 阶段 C：题型规格书 + 入库检查器（`sim_content.mjs`）

```bash
node sim_content.mjs
```

四块验收（A 规格书 / B 存量扫描 / C 待审题 / D 审核链路），实测 **16 通过 / 0 失败**：

- **规格书 schema（`question-spec.js`）**：`version / grade / term` 全部留空标「骨架待核对」（课本封面未核对，不按 `source` 推断）；只写 `ma-u01` 一份示范（考什么 / 5 种问法 / 干扰项规则 5 条 / 难度递增路径 2 级 / 易错点 4 条 / 禁止条款 4 条），不铺开四科。
- **入库检查器（`question-check.js`）4 条断言**：① 答案不泄漏在题干（选择题看正确项是否被紧邻断言词「最/是/等于/共有」直接陈述，填空题看答案是否以「=/得/是」形式写在题干；二选一列举、否定陈述、标点隔开均不误伤）；② 干扰项非随机词（选项 ≥3、互异、与正确项同类型、无空项/异常超长项）；③ 难度挂在规格书递增路径上（只查写了规格书的单元）；④ 题库级「不只换数字」（同知识点 ≥4 题但问法模板只有 1 种 → 标出）。

## 注意

- 脚本**只读项目代码、不写项目文件**，`localStorage` 是内存 Map，跑完即消失，不会污染真实数据。
- 模拟的是理想路径（连续 365 天打开、不切年级、不导入备份）。真实使用中清缓存 / 换设备会让去重记录归零，`sim_static.mjs` 专门量化这个场景。
- `sim_repeat.mjs` 末尾那句「容量缺口 54 倍」是拿「单日候选池」比「全年需求」的固定池视角，因为生成题每天重建，它**不是真实容量约束**，别拿它当扩容依据。真实约束是「问法模板数」，看 `sim_depth.mjs`。
- 逻辑题的 `source` 统一标为「情境题 · xxx」，**不冒充教材原题**。新增内容由生成器产出，答案与科学性请家长抽检，别只扩数量不扩质量。
