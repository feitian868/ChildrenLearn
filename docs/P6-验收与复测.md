## 二、跨设备 / 清缓存 / 换浏览器（sim_static 口径）

实测脚本：`node verify/sim_static.mjs`；版本 = 当前 v5 默认年级（g3）的 **pending 题池**。

- 该脚本每天抽到的题 **0 道是 v5 规格题**：单日池前缀为 `ma-g3` / `zhx-g3` / `scx-g3` / `en-g3` / `lg-*`，正则 `-(up|down)-u\d+-l\d+-k\d+-s\d+` 命中 0；所以 32.9% **不是 v5 35140 道内容的结论**。
- 前 200 天：题面重复率 **0%**。
- 第 201 天模拟换设备/清缓存/导入旧备份（`recentByDay`、`recentKeys` 归零）后，201~365 天题面重复率 **32.9%**（1983/6036）。
- 与 v4 对照：在 `d36e85c` 的临时 worktree 用同一脚本同一天数窗口重跑，得 **15.0%**（14.4% 未在项目内找到同口径记录，可能是更早快照）。差别不在每日题量（两版都是 36 题/天、6036 题/165 天），而在 P1 后的题池构成：`lg` 逻辑/场景题从 2521 升到 6333，`zhx`/`scx` 静态科题占比下降；清空去重后小池复用拉高重复率。
- 结论：
  - 换设备不会自动同步；换浏览器就是另一份 localStorage；清缓存/无痕模式直接归零。
  - 归零后不只是积分和进度丢失，365 天去重签名也丢失，固定静态/逻辑题会明显反复出现。
  - 唯一可靠做法：换设备前导出 JSON，在新设备导入；清理缓存前必须导出备份。
  - 这是纯前端、无账号架构的固有限制，v5 不解决，也不在 P6 范围内修。
