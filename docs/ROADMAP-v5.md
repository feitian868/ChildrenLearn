## 0. 为什么换模式（给真人，也给 AI）

v4 的「先握手 → 回贴状态 → 等一句继续 → 逐轮验收」是为**收尾态**设计的防越界机制，
适合「A~E 已做完、别乱动」。现在进入**主动建设期**，要覆盖 48 册教材，
那套口令会把 300 多个单元拆成几十轮对话，正是要避免的。

因此本轮起切换为：

| | v4 收尾态 | v5 建设态 |
|---|---|---|
| 授权 | 每轮一句「继续」 | **本文档一次性授权 P0~P6** |
| 节奏 | 每步贴结果再等 | **阶段内自推进，阶段末一页验收包** |
| 交互 | 十几次 | **6 次（每阶段一次抽样签字）+ 失败时** |
| 反馈 | 三块回报 | 验收包（红线表 + 抽样清单 + 差异说明） |
| 停下条件 | 等指令 | 红线失败 / 抽样签字 / 未定义决策 |

同样地，v4 的「三句开工授权」（8 道题已点通过 / 课本封面核对结果 / 发起下一内容轮）
**作废**——前两句已被下面的设计决策吸收，第三句由本文档整体授权替代。

## 2. 目标与规模（先算清楚，别拍脑袋）

### 2.1 目标

**以人教版新课标为主口径，把 1~6 年级上下册 × 四科 × 每个单元的知识点全部建成结构化课程包**，沿用 v4 已验证的模式：课程结构表 → 题型规格书 → 自动检查器 → 小批内容 → 审核闸门 → 生效 → 回归验证。

### 2.2 规模估算（按人教版各册常见单元数，AI 读代码/建包后以实测核对）

| 项 | 估算 |
|---|---|
| 册数 | 6 年级 × 2 册 × 4 科 = **48 册** |
| 单元数 | 数学 8 / 语文 8 / 英语 6 / 科学 4 单元每册 → **312 个单元** |
| 知识点 | 每单元 3 个 → **约 936 个 kid** |
| 问法规格 | 每知识点 3~5 种 → **2,808 ~ 4,680 份规格** |
| 内容产出 | 每规格 = 1 个参数化生成器 + 1 道人工审核过的静态样题 → **约 3,000~4,700 生成器 + 同量级静态样题** |
| 静态题源码体积 | 每道约 250B → **0.67~1.12 MB**，按 48 册分包后**每册约 24 KB** |
| mastery 常驻 | 936 kid × 120B ≈ **110 KB**（全量）；活跃窗口（当前册 + 复习中 ≈ 80 kid）≈ **9.4 KB** |

★ **两个容量必须分开看，这是全量化的关键**：
- **题目文本存在 JS 源码分包里，不进 localStorage** → 题库扩容**不会**撑爆 3.6MB 存储墙；
  新约束是**首屏加载体积**，靠「按 `edition/grade/term/subject` 分包 + 按需 import」解决（P0）。
- **localStorage 存的是做题记录 / 去重签名 / 掌握度 / 队列** → 它会随 kid 数增长。
  必须做 **mastery 分层**：活跃知识点常驻，历史知识点归档压缩（P0），
  否则 936 个 kid 的累积对象 + 复习队列会顶破 3.6MB。

### 2.3 内容供给的正确指标（避免重犯 v4 的错）

v4 的教训：`ma-u01` 补到「12 道可抽」后，每天仍只出 4~5 道，第 5 天起兜底 12.2%。
根因是「堆静态题」撞上模板上限 + 每项配额 + 知识点冷却 + 365 天避重。

**所以 v5 不堆题，堆「问法规格」。** 指标定义：

```
每知识点 ≥3 种问法规格（specId 互不相同）
每规格 ≥1 个参数化生成器（按日期种子每天重建唯一题面，沿用 v4 机制）
每规格 ≥1 道审核过的静态样题（用于家长核对与冷启动）
每知识点全年唯一题面供给 ≥ 该 kid 全年被调用次数 × 1.2
单元收敛 365 天兜底率 < 5%（v4 是 12.2%，这是必须跨过的线）
```

★ 用户最初抱怨「太模板化」的根因是**「一个知识点只有 1 种问法」**，不是「用了生成器」。
参数化生成器本身是 v4 已验证的 365 天不重复机制，保留；要消灭的是「单问法知识点」——
台账里那 20 个、以及全量建包时任何 `<3 specId` 的 kid，都算红线失败。

```
├─ math    : 人教版小学数学（1~6 年级上下册）
├─ chinese : 统编版小学语文（人教社出版，与数学同属主口径）
├─ english : 人教新起点（1~2 年级）+ 人教 PEP（3~6 年级）
│            ★ 两个 sub-track 用 track 字段区分，不要合并成一套
└─ science : 人教/鄂教版小学科学（沿用现有单元名，
             4~6 年级下册历史标注「按现行教材单元名」需在 P5 复核）
```

规则：

- `version / grade / term` **不再留空**，按 profile 填实；`source` 必须由结构化索引生成，
  **禁止再用题目自带字符串当出处**（这是 `annotateQuestion` 把「2 年级上册·表内乘法」
  挂进三上 `ma-u01` 的根因，P0 必须修掉）。
- 语文 `ZBOOK` 里「1~6 年级全是上册」的历史包袱在 P3 修正，上下册都要建。

- 若孩子学校实际用书不同：**只换 profile 数据包，不改代码、不改 kid 命名**。
  这才是「版本可配置」该有的样子，而不是每轮回贴问真人封面。

## 4. 数据规范（P0 落地，后续所有阶段依赖）

### 4.1 课程包结构（多册索引，替换单册 `course-map.js`）

```
data/course/
├── edition-renjiao-newcurriculum.json      // profile 元数据
├── math/g1-up.json … math/g6-down.json     // 12 册
├── chinese/…  english/…  science/…         // 各 12 册
└── index.js                                // 按 edition/grade/term/subject 懒加载
```

每册：
```js
{
  edition: 'renjiao-newcurriculum', subject: 'math',
  grade: 3, term: '上册',
  units: [{
    id: 'rj-math-g3-up-u01', name: '表内乘法（一）', order: 1,
    lessons: [{ id: '…-l01', name: '…' }],
    knowledge: [{
      id: 'rj-math-g3-up-u01-k01', name: '乘法的意义',
      prerequisites: ['rj-math-g2-up-u04-k02'],   // 继续只记录；启用条件见 P1
      difficulty: 2,                              // 4 档，见 P1
      objectives: ['能把连加改写成乘法'],
      typicalErrors: ['把 3+3+3 写成 3+3', '混淆乘数与被乘数'],
      specIds: ['…s01','…s02','…s03']             // ★ 必须 ≥3，红线
    }]
  }]
}
```

### 4.2 题目字段扩展（兼容 v4 现有字段，新增用可选）

```
edition / grade / term / unitId / lessonId / kid / specId / templateId
difficulty(1~4) / status(pending-review|approved|rejected) / reviewLevel(L0~L3)
source 必须由 [edition + grade + term + unit.order + lesson.name] 生成，
       不得由题目自带字符串提供
```

### 4.3 id 命名规范（一次性定死，避免全量建包后重映射）

```
{edition缩写}-{subject}-g{grade}-{up|down}-u{2位}-l{2位}-k{2位}
例：rj-math-g3-up-u01-l02-k03
题：rj-math-g3-up-u01-l02-k03-s02-gen / -static-01
```
★ v4 的 `ma-u01-k1` 等短 id 在 P0 做**一次性别名迁移**（`mastery.keys` 已有 alias 机制），
迁移后贴「迁移前后 kid 数 / 掌握度连续性」证据。之后 id 冻结。

### 4.4 内容生产流水线（P2~P5 统一，AI 按此自跑）

```
① 规格书 question-spec：每个 kid 3~5 种问法
     ├ 考什么（认知层级，不是「换数字」）
     ├ 3~5 种问法规格 + 难度递增路径
     ├ 干扰项构造规则：必须是 typicalErrors 里的真实易错点
     └ 禁止：答案泄漏在题干 / 只换数字不改认知层级 / 超纲词
② 生成器 + 静态样题：每规格 1 个参数化生成器 + 1 道样题
③ L0 结构校验（自动）：id 唯一、字段齐、unit/lesson/kid 挂载有效、
     edition/grade/term 匹配、specId≥3、无跨年级错挂、source 由索引生成
④ L1 内容校验（自动，扩展 question-check.js）：
     v4 四断言 + ★ 新增三条：
       答案唯一性（两种自洽解判废，对应已下线的 ol-g3-zh/ol-g6-tl）
       超纲词表（按 grade 拦截，对应 ol-g1-xd）
       解析结论一致性（★ 补 v4 已知盲区：解析里出现正确数值
                        但最终结论指向错误值，必须抓到）
⑤ L2/L3 审核（分级，见 4.5）→ status: approved
⑥ 灰度生效：先只进「复习题 / 拓展题」池，连续 7 天无驳回且回归通过
             → 才进「当前单元教材题」池
⑦ 回归：结构脚本 + 12 脚本 + 单元收敛 365 天模拟
```

### 4.5 ★ 审核分级（v4 逐题点通过无法扩展到 48 册，必须演进）

| 级别 | 方式 | 覆盖范围 |
|---|---|---|
| L0 | 自动结构校验 | 100% |
| L1 | 自动内容校验（含新增 3 断言） | 100% |
| L2 | **批次抽样人工**：每册抽样 ≥10 道、每 kid 至少 1 道代表题 | 每阶段末一次，真人一页签字 |
| L3 | **全量人工**：仅高风险类别（开放题、推理/判断题、科学解释、英语语境题、奥数、任何 L1 曾判废过的规格） | 每阶段末随抽样包一起交 |

规则：
- 新内容**默认 `pending-review`、不进抽题池**这条闸门保留（不倒退）；
- 但**放行单位从「逐题」改为「批次」**：真人一次审完该阶段抽样包并签字，
  AI 才把该批同规格的其余内容批量转 `approved`（同规格 = 已通过 L0+L1 + 抽样覆盖）；
- L1 判废的题**自动 rejected**，不进人工队列，记录原因；
- 保留**批量驳回 / 一键回滚到上一阶段 commit** 能力；
- 每阶段**只有一次**真人交互（审抽样包），不再逐题点 8 次、也不再每轮换口令。

> 这是本设计里唯一需要真人拍板一次的地方：**是否接受「批次抽样 + 同规格批量放行」**。
> 若不接受，全量 48 册按 v4 逐题审核估算需审 3,000~4,700 次，工程上不可行。
> 建议接受；AI 在 P0 验收包里把这一条列为「待确认」，真人回一句即可，之后不再问。

## 5. 年级差异化引擎（P1，v4 没做完的核心诉求）

v4 现状：`taskCountFor(subject, weekday)` 无 grade 参数，1~6 年级每日题量完全相同、
`PASS_LINE=3` 全年级统一、只有两档难度、自适应只看近 7 天总正确率。
**P1 是唯一允许解除 v4 常数禁区的阶段**，改完必须贴 1~6 年级对照表。

建议值（**实测校准，非硬编码圣经**）：

| 年级 | 每日任务项数 | 每题组题量 | 达标线 | 难度档 | 儿童适配 |
|---|---|---|---|---|---|
| 1 | 2 | 3 | 2/3 | 1~2 | 全科目注音、TTS、题干 ≤20 字 |
| 2 | 2~3 | 3~4 | 2/3 | 1~2 | 注音、短情境 |
| 3 | 3 | 4 | 3/4 | 1~3 | 逐步撤注音 |
| 4 | 3 | 4 | 3/4 | 1~3 | 多步推理 |
| 5 | 3 | 4 | 3/4 | 2~4 | 抽象/迁移 |
| 6 | 3 | 4 | 3/4 | 2~4 | 综合/拔高 |

> 已按实测收敛（v5-P1）：5、6 年级与 4 年级同为 3 项（4~6 稳定期）。六年级原建议 4 项
> 会到 17 项 / 68 题一天（v4 三年级 36 题的 1.89 倍），故不再加项；年级差异由难度档位、
> 达标线与拔高题承担。

同时：
- `adaptTarget()` 从「近 7 天**总**正确率」改为「**按 kid 的掌握度 + 错因**」调难度，
  与 B 轮 `mastery` 打通（不再两套逻辑各算各的）；
- `LEVEL_LABEL` 从 2 档扩到 4 档（识记 / 理解 / 应用 / 迁移），
  题目 `difficulty` 与规格书难度递增路径对齐；
- `prerequisites`：在 **P2 数学包通过结构校验后**才启用参与计算（v4 规定「只记录」，
  课本 profile 已定 + 单元顺序复核完即可解冻），启用前贴先修链闭环检测报告
  （无环、无跨册断裂、无指向未学单元）；
- `QUESTIONS_PER_TASK=4` **不动**（仍为硬禁区），年级差异靠**项数**与**达标线**实现，
  不靠改每题组题量——避免再次撞上 `allowShort` / `PASS_LINE` 的 P0 冲突（v4 A 轮教训）。

## 6. 阶段划分与验收门禁（**AI 按此自推进，不等「继续」**）

统一规则：
- 阶段内自由推进；**每阶段末回贴一页验收包**（红线表 + 抽样清单 + 差异说明 + 两栏）；
- 红线**全过 → 自动进下一阶段**并回贴一页摘要，**不等「继续」**；
- 任一红线失败 / 需要 L2 抽样签字 / 遇到未定义决策 → **停下**回贴，等真人一句；
- 每阶段通过后做一次**阶段 commit**（不 push），见第 8 节。

### P0 · 基座扩展（不生成题目）
- 多册 `data/course/` 分包 + 懒加载索引；`editionProfile` 落地；
- `annotateQuestion` → 改为由结构化索引生成 source，**跨年级错挂清零**；
- id 规范冻结 + v4 `ma-u01-k1` 类短 id 别名迁移（贴掌握度连续性证据）；
- mastery 分层（活跃常驻 / 历史归档压缩）、recentQuestions 按册窗口；
- 首屏只加载当前册，贴 bundle 体积对比。
**验收**：`sim_structure` / `sim_edition` / `sim_bundle` 全过；迁移不丢掌握度；
12 脚本防回归全过；跨年级错挂 = 0；365 天完整答题 ≤3.6MB；首屏 JS ≤ 现有 +20%。

### P1 · 年级差异化引擎（不生成题目）

## 9. 不做的事（防止 AI 顺手跑偏）

- **不推倒重来**：v4 的 mastery / reviewQueue / 周报 / 检查器 / 审核闸门 / 听说练习去评分化 /

- **不整体格式化大文件**（遗留 BOM/CRLF 会污染 diff）。
